# Migration plan: `GfmPreviewWithToc` -> `gfm-preview.nvim`

## Decisions locked in

| Topic | Choice |
|--------|--------|
| Scope | Full feature parity **minus TOC** |
| Commands | Buffer, selection-required, annotation |
| Delivery | System browser only (`file://` temp HTML) |
| Layout | Standalone plugin at `~/Projects/gfm-preview.nvim` |
| Impl | Pure Lua port |
| Tests | `plenary.busted`, strict RED/GREEN/refactor |
| Keymap | `<leader>mp` (buffer/selection-aware) |

External tools already present: `pandoc`, `pandoc-crossref`, `d2`, `~/bin/lit-annotation`. CDN assets stay as in Sublime (MathJax, mermaid, KaTeX, pseudocode.js, viz.js, github-markdown-css, Font Awesome). Excalidraw still goes through Kroki.

## Feature map (Sublime -> Neovim)

| Sublime | Neovim module / command | Notes |
|---------|-------------------------|--------|
| `preview_markdown` (no TOC path) | `gfm_preview.preview(text)` | Simple HTML shell only |
| Sticky TOC path | **dropped** | No `--toc`, no sticky CSS/nav |
| Selection-aware full cmd | `:GfmPreview` + `<leader>mp` | Visual if non-empty, else whole buffer |
| Selection-required | `:GfmPreviewSelection` | Error notify if empty |
| Annotation | `:GfmPreviewAnnotation` | `lit-annotation` extract; notify if none |
| Mermaid preprocess | `preprocess.mermaid` | `\n` -> `<br/>`, HTML-escape, `<pre class="mermaid">` |
| Pseudocode + YAML macros | `preprocess.pseudocode` | front matter + inline `\newcommand`, sanitize |
| Graphviz/dot | `preprocess.graphviz` | hidden `div.graphviz-src` |
| D2 | `preprocess.d2` | `d2` CLI -> inline SVG |
| Excalidraw | `preprocess.excalidraw` | Kroki POST -> SVG |
| Callouts | `preprocess.callouts` | Obsidian `> [!type]` -> fenced divs + CSS/JS |
| MathJax header | `assets` | same CDN + config |
| pandoc-crossref | `pandoc` argv | keep filter + `codeBlockCaptions` |
| GFM CSS | `pandoc` argv | github-markdown-css CDN |
| Browser open | `browser.open(path)` | `vim.ui.open` / `open` on macOS |

Preprocess order (match Sublime):

1. mermaid
2. pseudocode
3. graphviz
4. d2
5. excalidraw
6. callouts

Then write `input.md` and run pandoc.

## Public API (sketch)

```lua
require("gfm_preview").setup({
  pandoc = "pandoc",
  pandoc_crossref = "pandoc-crossref",
  d2 = "d2",
  lit_annotation = vim.fn.expand("~/bin/lit-annotation"),
  open_browser = true, -- false useful in tests
  keymap = "<leader>mp", -- false to disable
})

require("gfm_preview").preview_buffer()
require("gfm_preview").preview_selection()
require("gfm_preview").preview_annotation()
require("gfm_preview").preview(md_text) -- core; returns html_path or err
```

Core pure surface for TDD: preprocess functions and pandoc argv builder take strings/tables and return strings/tables - no Neovim UI in the hot path.

## Strict TDD workflow

### Rules

1. **No production code without a failing test** for that behavior.
2. One behavior per cycle: write test -> run (RED) -> minimal impl (GREEN) -> refactor.
3. Prefer **pure unit tests** for string transforms; integration tests only at the seams (CLI, pandoc).
4. External side effects are injected:
   - `run_cmd(argv, opts) -> { code, stdout, stderr }`
   - `http_post(url, body) -> { ok, body, err }`
   - `open_url(url)`
   - So d2 / Kroki / browser / lit-annotation are mockable.
5. Fixtures under `tests/fixtures/`; assert on substrings/markers, not full HTML blobs (except small pure transforms).
6. `Makefile`:

```make
test:
        nvim --headless -u tests/minimal_init.lua \
          -c "PlenaryBustedDirectory tests/ {minimal_init = 'tests/minimal_init.lua'}"
```

### Implementation order (each step is its own RED/GREEN loop)

**Phase 0 - Scaffold**

- Create repo skeleton, `minimal_init.lua`, Makefile, empty `setup()`.
- Smoke test: `require("gfm_preview")` succeeds.
- Lazy plugin file in nvim config pointing at `dir = ~/Projects/gfm-preview.nvim`.

**Phase 1 - Pure HTML helpers**

- `html_escape`: `& < >` (and only those, matching Sublime).
- Tests: each entity, identity on clean text, combined.

**Phase 2 - Mermaid**

- Tests: fence -> `<pre class="mermaid">`; `\n` to `<br/>`; `<fa:...>` escaped; non-mermaid fences untouched.
- Implement `preprocess.mermaid`.

**Phase 3 - Graphviz**

- Tests: ` ```graphviz` / ` ```dot` -> hidden div; content escaped; other fences ok.
- Implement.

**Phase 4 - Callouts**

- Tests per type + aliases (`hint`->`tip`, etc.), fold `+`/`-`, custom title, body `>` stripping, unknown type falls back to note icon styling path.
- Port icon/CSS/JS tables into `assets` / `callouts`.
- Implement `_preprocess_callouts` logic in Lua.

**Phase 5 - Pseudocode / macros**

- Unit tests for:
  - `_yaml_unescape` (simple, `\n`, `\uXXXX`, unknown escape)
  - `_parse_front_matter_macros`
  - `_expand_pseudocode_macros` (0-arg, 1-arg, inline override, negative lookahead `\se` vs `\search`)
  - `_sanitize_pseudocode` (`\label`, algorithmic `[1]`, `\textcolor`, bare break/continue)
  - fence `pseudocode` / `algorithm` -> `<pre class="pseudocode">`
- Implement in that order (smallest pure functions first).

**Phase 6 - D2**

- Tests with injected runner: success embeds SVG wrapper; nonzero -> error pre; missing binary -> install message; timeout path.
- Implement with temp files + cleanup in `finally`.

**Phase 7 - Excalidraw**

- Tests with injected `http_post`: 200 SVG; HTTP error body; network failure.
- Implement Kroki client via `vim.system` or injectable HTTP.

**Phase 8 - Pipeline**

- `preprocess.run(md)` applies steps in Sublime order.
- Test multi-feature fixture: mermaid + callout + math source still present for pandoc.

**Phase 9 - Annotation extract**

- Inject `run_cmd` for `lit-annotation`.
- Tests: delimited `--pretty`; bare `--bare --pretty`; single annotation with `body`; failure/timeout returns original; multi-annotation returns original.

**Phase 10 - Pandoc orchestration**

- Unit tests on argv:
  - format `markdown+tex_math_dollars+tex_math_single_backslash`
  - `-yaml_metadata_block` when text does **not** start with `---`
  - crossref filter, captions, standalone, wrap=none, GFM css
  - include-before/after/header paths
  - **no** `--toc`
- Optional live test (skip if no pandoc): plain.md produces HTML containing `markdown-body` and github css link.
- Header assets: MathJax, mermaid, pseudocode, graphviz, d2/excalidraw styles, callout CSS/JS, dark-mode style - **no** TOC script/CSS.

**Phase 11 - Browser + source extraction**

- `browser.open`: builds `file://` URL; injectable open fn.
- `source.buffer_or_visual()` / `source.selection_only()` using Neovim APIs - test with plenary buffer helpers.
- Commands + `<leader>mp` in normal (whole buffer) and visual (selection).
- End-to-end happy path test with `open_browser = false` and mocked pandoc or real pandoc + assert html_path contents.

**Phase 12 - Harden / refactor**

- Error notifies (`vim.notify`) for pandoc failure, empty selection, no annotation body.
- Temp dir cleanup policy (keep last preview for debug vs wipe - default: leave temp like Sublime).
- README: deps, commands, keymap, feature list, how to run tests.

## Pandoc command (no TOC) - target shape

```
pandoc
  -f markdown+tex_math_dollars+tex_math_single_backslash[-yaml_metadata_block]
  --filter pandoc-crossref
  -M codeBlockCaptions=true
  -t html
  <md_path> -o <html_path>
  --standalone --wrap=none
  --css=https://cdnjs.cloudflare.com/ajax/libs/github-markdown-css/5.8.1/github-markdown.min.css
  --include-before-body=...   # SIMPLE_HTML_START
  --include-after-body=...    # SIMPLE_HTML_END
  --include-in-header=...     # dark mode + mathjax + mermaid + ... + callouts
```

## Open items I am **not** blocking on (sensible defaults)

- Temp dir prefix: `gfm_preview_`
- On pandoc failure: `vim.notify(..., ERROR)` and do not open browser
- Annotation CLI default: `~/bin/lit-annotation`
- Visual mode `<leader>mp`: uses selection; normal mode: whole buffer
- Extra commands without default maps: `:GfmPreviewSelection`, `:GfmPreviewAnnotation`
